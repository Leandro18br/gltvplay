## Integration rules
- MegaEmbed URLs are built from admin-editable templates in site_settings by `src/lib/integrations/megaembed.ts` and saved as ordinary embed sources. Why: reuse existing source priority, authorization and player.
- M3U lists (`src/lib/integrations/m3u*.ts`): full list URL lives only in service-role `m3u_list_secrets`; Sincronizar only INDEXES the list into service-role `m3u_items` via short, checkpointed server steps (byte offset + Range when supported, batched upserts, chunked finalize RPCs under the 8s statement timeout); the main catalog changes only through explicit admin import of selected items (few per request, dedupe TMDB → item.content_id → title+year → season/episode → stream URL), series episodes go through the set-based service-role RPC `m3u_import_series_chunk` (adaptive chunk size, transient retry, SKIP LOCKED, unique-key dedupe), producing ordinary `playback_sources` tagged `m3u_list_id`, flagged `unavailable_since` instead of deleted. Why: a single-request sync exceeded the worker CPU limit on 100k+ lists, and the public site must only show deliberately imported content.
- M3U finalize refreshes imported links in small keyset chunks (adaptive size, cursor in index_flags); never one UPDATE over all sources. Why: a single statement exceeded the 8s database limit on ~98k links.

- Sync-failure AI diagnosis runs server-side in `src/lib/integrations/diagnose.functions.ts` (staff-only, URLs/credentials redacted before sending, read-only advice). Why: secrets never reach the model and AI never changes data.
- BugouMods (`bugoumods*.ts`): staff-only server fetch of the VIP series list and `series_info`; vtoken kept in BUGOUMODS_VTOKEN and only embedded in staff-only stored VIP player URLs; episodes get the provider "Embed VIP" player URL (player.php ... &vtoken=&embed=vip, the format of the provider own Embed VIP button) built server-side as an embed source (external_ref bugoumods:<id>); re-import upgrades older Free URLs, reusing existing series/seasons/episodes without overwriting. Why: token secrecy, no duplicates, no catalog overwrite.
- BugouMods series token comes from the api_integrations row kind 'series' + provider 'bugoumods_series' (service-role `api_credentials`, env BUGOUMODS_VTOKEN only as fallback); its card on APIs e Integrações reuses the series importer, and provider calls are logged in api_request_logs. Why: one API manager for live and series without separate importers.
- BugouMods series searches read the staff-only `bugou_catalog` index (refreshed from the single full provider list every 6h or on demand; rows absent from the current list are dropped because series_info no longer knows their ids); imports run through resumable `bugou_import_jobs/items` driven by short leased server calls, one series at a time with retries. Why: provider has no search/pagination and workers are stateless.
- Live-channel APIs (`live*.ts`, api_integrations.kind 'live' + `provider` naming a verified format): token only in service-role `api_credentials`; the single provider list is mirrored into staff-only `live_catalog` without play links; imports are leased `bugou_import_jobs` (kind 'live') that refetch the list per step and write channels (unique api_integration_id+external_id) plus embed sources keeping the provider link verbatim (external_ref bugoumods-live:<id>); never deletes. Why: SSRF-safe, idempotent, resumable bulk import without exposing tokens.
- Series and Channels admin pages open the same importers used by APIs e Integrações (BugouSeriesButton, LiveChannelsButton) with whole-category jobs; no per-page tokens or configs. Why: one integration config, no duplicate screens.
- BugouMods series queue calls series_info once per series (cached on the item until done), paced by the integration's rate_limit_per_minute with adaptive slowdown; HTTP 429 is never retried inline: the item is deferred (Retry-After or jittered backoff, helpers in `ratelimit.ts`), every series job pauses via throttle_until, and after a capped number of 429s it waits for manual retry. Why: bursts of retries caused 429s and lost progress.
- A series import item is done only after re-reading the DB confirms every API episode exists under the right season with its VIP source (matched by provider episode id); series with no provider episodes are not created. Why: titles alone were reported as complete imports.
- BugouMods full catalogs (series and live) are indexed through the provider's paginated `home_data` + `category_page` endpoints by `catalog-sync.functions.ts` (client-driven short steps, cursor resumable from localStorage, paced by the integration rate limit, 429 waits); category membership lives in `bugou_catalog_categories` / `live_catalog_categories` and all per-category counts, filters and whole-category jobs read them; the `c=all` list (50 per category) never deletes index rows. Why: `c=all` silently truncated categories to 50 items.
- Live channels missing from the `c=all` list get their VIP link from `liveVipLink` (byte-identical to the provider's list format, verified on all 1,821 listed channels). Why: imports must reach channels beyond the 50-per-category list.
- Admin name searches for BugouMods series/channels call the provider's own `global_search` once per search via `api-search.functions.ts` (token server-side) and add missing hits to the staff index without category; category browsing still reads the synced index. Why: real API search, importable results, no catalog download per search.
- API search dialogs use the shared `ApiSearchBar` (field/button never disabled, text owned by the bar) and discard superseded responses by request sequence. Why: a disabled submit button blocks the Android keyboard's search key and late responses overwrote newer results.
